[https\://gemini.google.com/app/8fb661de1f73104f](https://gemini.google.com/app/8fb661de1f73104f)

*User prompt: review並提出改善方案*

Response: 上傳的 mapping\_elf 專案壓縮檔因包含大量二進位圖檔（如多個 splash.png 與 promo-01-intro-a.png）及 Deflate 壓縮磁區，導致純文字串流被圖片二進位資料填滿而無法直接展開檢視內部原始碼文本。不過從壓縮檔內的完整目錄結構與檔案配置清單中，仍可清楚看出此專案是一個結合 **Claude Code Multi-Agent 架構**與 **Capacitor Android 原生封裝**的離線地圖與配速分析應用程式。

以下針對目前可見的專案架構、Agent/Skill 設計、Android 原生層配置與檔案管理進行審查，並提出具體改善方案：

## **1\. Claude Agent 與 Skill 架構治理**

### **現況與問題點**

> * **Agent 與 Skill 1:1 鏡像重疊**：.claude/agents/ 目錄下的 11 個定義檔（如 mapping-elf-core-modules.md、mapping-elf-ui-event-logic.md 等）與 .claude/skills/ 下的 11 個子目錄（各包含一個 SKILL.md）採用完全相同的命名與對應結構。這種設計極易導致系統提示詞（Prompt）與領域規則在兩處重複撰寫，增加維護成本與規則不同步的風險。  
> * **核心模組參考文件階層不一致**：在 .claude/skills/mapping-elf-core-modules/references/ 中，pace-engine.md 另外延伸出子資料夾 pace-engine/formulas.md，而同層級的 export-parser.md、offline-map.md、routing.md、weather-table.md 皆為單一平面檔案。  
> * **非開發類技能與工程驗證混雜**：mapping-elf-market-research-analysis（含 research-workflow.md）屬於市場調研性質，與負責程式碼實作及驗證的 mapping-elf-core-modules、mapping-elf-review、mapping-elf-verifier 等工程模組放在同一層級，容易增加 mapping-elf-sub-agent-coordinator 協調路由時的判斷複雜度。

### **改善方案**

> 1. **落實單一事實來源（SSOT）**：將領域知識、數值公式與資料契約統一集中於 .claude/skills/\*/SKILL.md 與其 references/ 目錄中（如 spatial-numeric-rules.md、data-contracts.md、event-flow.md）；.claude/agents/\*.md 則僅保留輕量化的角色職責、可用工具（Tools）權限與呼叫對應 Skill 的指令，避免重複記述業務邏輯。  
> 2. **整併品質把關角色**：釐清 mapping-elf-review 與 mapping-elf-verifier 的職責邊界（例如前者專責靜態 Code Review 與架構合規，後者專責執行測試與建置驗證），若兩者檢查項目高度重疊，建議合併為單一 QA Agent 以減少 Sub-agent 切換開銷。  
> 3. **統一 references/ 目錄結構**：將 pace-engine/formulas.md 改名並拉平為 pace-engine-formulas.md（或直接併入 pace-engine.md），使 references/ 下維持一致的單層結構，方便 Agent 快速檢索。

## **2\. Android 原生層與測試配置（Capacitor）**

### **現況與問題點**

> * **測試套件命名空間（Package Name）未同步**：正式環境的主程式 MainActivity.java 與自訂外掛 OfflineMapsPlugin.java 已放置於 com/mappingelf/app/ 路徑下；但單元測試 ExampleUnitTest.java 與儀器測試 ExampleInstrumentedTest.java 卻仍停留在 Capacitor 初始範本路徑 com/getcapacitor/myapp/。  
> * **缺乏針對自訂原生外掛的實質測試**：專案包含自訂的 OfflineMapsPlugin.java，但測試目錄下僅有預設的 ExampleUnitTest.java 與 ExampleInstrumentedTest.java 樣板檔案。

### **改善方案**

> 1. **修正測試套件路徑**：將 android/app/src/test/java/ 與 android/app/src/androidTest/java/ 下的目錄結構由 com/getcapacitor/myapp/ 遷移至 com/mappingelf/app/，確保與 AndroidManifest.xml 及 build.gradle 的 namespace / applicationId 一致。  
> 2. **補齊 OfflineMapsPlugin 測試**：移除無實際作用的 ExampleUnitTest.java 樣板，針對 OfflineMapsPlugin.java 的離線圖資讀取、快取路徑解析與例外處理新增對應的單元測試。

## **3\. 儲存庫體積與靜態資源管理（Repo Bloat）**

### **現況與問題點**

> * **傳統啟動畫面（Splash Screen）造成嚴重檔案膨脹**：android/app/src/main/res/ 下包含 drawable-land-\*、drawable-port-\*、drawable-land-night-\*、drawable-port-night-\*（涵蓋 ldpi、mdpi、hdpi、xhdpi、xxhdpi、xxxhdpi）等超過 25 個大型 splash.png 點陣圖檔。這正是導致壓縮檔體積暴增、佔用大量儲存空間的主因。  
> * **本地設定檔被納入打包**：.claude/settings.local.json 出現在專案打包清單中，此類檔案通常包含開發者本機環境或個人權限設定，不應隨專案發布或進入版控。  
> * **大型行銷素材存放於主程式碼庫**：assets/promos/promo-01-intro-a.png 為高解析度宣傳圖檔，直接放在核心專案目錄中會拖慢 Clone 與 CI/CD 建置速度。

### **改善方案**

> 1. **升級 Android 12+ SplashScreen API**：移除數十個 drawable-\*-\*/splash.png 全螢幕點陣圖，改在 android/app/src/main/res/values/styles.xml 中使用 AndroidX core-splashscreen 搭配應用程式圖示（ic\_launcher\_foreground.xml）與背景色設定，可瞬間減少數十 MB 的無效圖檔體積。  
> 2. **更新 .gitignore 規則**：在根目錄的 .gitignore 中加入 .claude/settings.local.json（或 \*.local.json），並將其從 Git 追蹤中移除（git rm \--cached .claude/settings.local.json）。  
> 3. **分離商店宣傳素材**：assets/ 目錄下僅保留 Capacitor 圖示生成工具所需的 icon-background.png、icon-foreground.png、icon-only.png；將 assets/promos/ 移至外部雲端空間或改由 Git LFS 追蹤。

## **4\. 根目錄文件結構整理**

### **現況與問題點**

> * **根目錄技術文件散落**：根目錄同時放有 CLAUDE.md、README.md、TODO.md 與 Windy\_API.md。其中 Windy\_API.md 屬於特定第三方 API 串接說明，與 .claude/skills/mapping-elf-core-modules/references/weather-table.md 高度相關，直接放在根目錄較缺乏系統性歸檔。

### **改善方案**

> * 建立 docs/ 資料夾存放 Windy\_API.md 與 TODO.md，或將 Windy\_API.md 整合進 .claude/skills/mapping-elf-core-modules/references/ 中供 Agent 直接參照，讓根目錄保持乾淨（僅留 README.md、LICENSE、CLAUDE.md）。
